## Об’єкт і порядок перевірки

Перевірено збірку локальної основи, повний набір тестів, відповідність очікувань SRS і зв’язки BL/TC → тест → дефект. Основні юніт-класи зібрано з п’яти частин в окремій папці. Опублікований main відтворюється з нового клону за README після злиття внесків; його результат додається в цей протокол.

## Що довелося з’ясовувати

Натискання Submit після прокручування спричиняло ElementClickInterceptedException. Миттєве прокручування й повторний пошук у явному очікуванні усунули нестабільність. Для чотирьох кодів BL-10 виявлено різні назви в SRS і API; їх зіставлення наведено в матриці. Неповністю автоматизовані кроки ручних кейсів перелічено в ui-scenarios.md.

У Linux-копії для контейнера задано шлях до браузера, --no-sandbox та --disable-dev-shm-usage; для мережевого TLS-посередника — --ignore-certificate-errors. Ці параметри стосуються перевірочного середовища, функціональні входи й очікування тестів збережено. Maven повторно використав завантажені залежності в offline-режимі; UI звертався до живого demo.
