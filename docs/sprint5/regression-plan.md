## Етапи регресії

| Етап | Робота | Результат |
|---|---|---|
| W10, дні 1–3 | Прогін JUnit і WebDriver, повторне виконання TC-001–049 та кроків відтворення дефектів | Журнал регресії, звіти Surefire |
| W10, дні 4–6 | Порівняння результатів, верифікація дефектів, звірка покриття та метрик | Оновлений трекер, матриця простежуваності |
| W11 | Оцінка готовності до випуску, рецензія, аудит, ретроспектива та peer-review | Звіт про якість і матеріали команди |
| W12 | Захист із демонстрацією автопрогону | Презентація результатів |

Журнал містить дату, відповідального за планом та фактичний результат кожної перевірки. Виконавця ретесту й дату зазначено в коментарях до дефектів у трекері. Для Failed зазначається ID дефекту, для Blocked — недоступна передумова та причина. Покриття визначається за зв’язками вимог із тестами. У метриках прогону кожен ручний кейс, сценарій WebDriver і параметризоване виконання JUnit рахується окремо. Failure і Error у звітах Surefire враховуються як Failed зі збереженням типу результату.

## Критерії готовності до випуску

| ID | Критерій | Обґрунтування |
|---|---|---|
| К1 | 0 відкритих дефектів рівня Blocker або Critical | Випуск потребує працездатного бронювання та контролю доступу |
| К2 | Покрито ≥90% активних вимог і 100% вимог High | Вимоги High мають бути повністю охоплені перевірками |
| К3 | Pass rate ≥95%. Допустимі Failed лише для Minor або Trivial із пріоритетом P3 | Допустимі лише відхилення з незначним впливом |
| К4 | 0 відкритих регресійних дефектів | Поведінка, підтверджена на v1.0.0, має зберігатися у v2.0.0 |
| К5 | Кожен Blocked перевиконано або виключено з обґрунтуванням | Ризик неперевіреної поведінки має бути визначений |

Go застосовується за виконання всіх критеріїв. Порушення К1 або К4 веде до No-Go. Для одного відхилення за К2, К3 або К5 можливий умовний Go з переліком дій і датою повторної перевірки. Кілька умовних відхилень ведуть до No-Go.

Редакція від 20.11.2026 зберігає початкові критерії плану від 17.11.2026, включно з К5. Запис причини блокування та ризику не замінює повторну перевірку або обґрунтоване рішення про виключення. У журналі зберігаються всі кейси й результати; обґрунтоване виключення з оцінки готовності не означає видалення запису або заміну Blocked на Passed. У поточному прогоні 17 Blocked збережено без виключення.
