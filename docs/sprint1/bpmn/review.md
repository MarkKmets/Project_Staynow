## Чек-лист перевірки BPMN-моделі (10 пунктів)

| № | Пункт перевірки | Так / Ні | Зауваження та коментарі рецензента |
| :-: | :--- | :-: | :--- |
| **1** | Кожен процес має щонайменше одну початкову й одну кінцеву подію; немає дій без вхідного або вихідного потоку | `` | — |
| **2** | Учасники відображені пулами, підрозділи або ролі всередині організації — доріжками; кожна дія лежить у доріжці свого виконавця | `` | — |
| **3** | Потоки керування не перетинають межі пулів; взаємодія між пулами показана потоками повідомлень | `` | - |
| **4** | Кожен шлюз, що розгалужує, має умови на вихідних потоках (або позначений потік за замовчуванням); тип шлюзу (ексклюзивний, паралельний, інклюзивний, за подіями) відповідає логіці | `` | — |
| **5** | Паралельне розгалуження закрите парним шлюзом того самого типу; немає «висячих» гілок | `` | — |
| **6** | Назви дій — дієслово + об'єкт («Перевірити наявність товару»), назви подій — стан («Замовлення оплачено») | `` | - |
| **7** | Проміжні події (таймер, повідомлення, помилка) використані там, де процес чекає або реагує на зовнішню подію | `` | — |
| **8** | Артефакти даних (об'єкти даних, сховища) та анотації присутні там, де вони пояснюють, з чим працює дія | `` | — |
| **9** | Підпроцеси використано для повторюваних або складних фрагментів; діаграма читається без пояснень автора | `` | — |
| **10** | Модель відповідає легенді продукту: учасники, кроки й рішення узгоджені з описом процесу в каталозі; альтернативні й помилкові сценарії (відмова, скасування) показані | `` | — |

### Позначення пунктів

| № | Критерій |
| :-: | :--- |
| **1** | Початкова й кінцева події; відсутність дій без входу/виходу |
